# 音频自动提取《三角洲行动》口琴谱设计

## 目标

建立一套 Windows 本地工具，用户把 MP3、WAV 或 FLAC 拖到批处理文件上后，工具自动提取单音主旋律，搜索最适合《三角洲行动》口琴的移调，并输出可以手动演奏的连续按键谱和详细节奏谱。第一版不承诺支持 M4A；用户可先将其转换为 WAV 或 MP3。

工具只生成乐谱、MIDI 和离线试听，不生成鼠标宏，不向游戏发送按键。

## 使用方式

### 主要入口

- 将单个音频文件拖到项目根目录下的 `提取口琴谱.bat`。
- 批处理文件显示当前阶段、输出位置和可理解的错误信息。
- 处理成功后自动打开输出文件夹。

### 命令行入口

```powershell
python scripts/extract_harmonica_score.py "D:\Music\song.mp3"
```

可选参数：

- `--output <目录>`：指定输出根目录，默认为 `output`。
- `--keep-stems`：保留人声和伴奏分离文件；拖放入口默认开启。
- `--force`：覆盖同名歌曲已有的生成结果。

## 系统结构

新建一个可编排的主程序，并将现有算法拆成职责明确的模块：

- `scripts/extract_harmonica_score.py`：参数解析、流程编排、进度和错误报告。
- `scripts/harmonica/audio.py`：音频读取、人声分离、转换为分析用单声道波形。
- `scripts/harmonica/transcription.py`：pYIN 音高跟踪、发音起点检测、重复音拆分、滑音抑制和低置信度过滤。
- `scripts/harmonica/rhythm.py`：从伴奏中检测速度和拍点，将音符开始与结束量化到十六分音符网格。
- `scripts/harmonica/instrument.py`：游戏口琴音域、键位、鼠标修饰键、移调评分和按键记号。
- `scripts/harmonica/render.py`：连续按键谱、详细节奏谱、CSV、MIDI 和 WAV 试听的输出。

现有 `transcribe_vocals.py` 和 `build_game_score.py` 保留作为《晴天》验证基线，新工具不再依赖在线 MIDI 参考文件。

## 处理流程

1. 验证输入路径、扩展名和文件可读性。
2. 使用 Demucs `htdemucs` 二轨模式分离 `vocals.wav` 与 `no_vocals.wav`。
3. 将人声转换为 22,050 Hz 单声道，计算 RMS 能量、pYIN 基频和有声概率。
4. 使用自适应能量门限去除安静区、残留伴奏和低置信度帧。
5. 对半音量化后的音高做中值/众数平滑，抑制颤音和短促跨半音误检。
6. 在人声轨上检测发音起点；当连续音高相同但出现新的有效起点时，拆成多个同音音符。
7. 合并极短的伪音符，保留有明确起点或稳定音高的短音。
8. 从伴奏轨检测拍点；如果自动速度低于 45 BPM 或高于 210 BPM，则视为不可信并使用基于音符间隔的网格估计。
9. 将音符量化到拍点内最近的十六分音符，但保留至少一格的音符长度。
10. 枚举所有能容纳完整音域的半音移调，用以下顺序评分：超界音数、鼠标状态切换次数、需要鼠标的音符数、升半音音符数、移调绝对值。
11. 使用最优移调生成所有输出并写入同一磁盘上的临时目录；所有文件成功后再一次性移入最终目录。使用 `--force` 时，也只在新结果全部生成并验证后替换旧目录，失败时旧结果保持不变。

## 发音起点与重复音规则

- 起点候选来自谱通量能量突变和频谱通量突变。
- 起点必须与有声人声区间重合，并与前一起点相隔至少 60 ms。
- 相同量化音高中出现有效起点时，允许拆分重复音。
- 只有当新片段长度至少 70 ms，且起点前后音高中值差不超过 70 音分时，才将其视为同音重复。
- 当起点与子音节或呼吸噪声特征一致且乏稳定音高时，不生成新音符。

## 自动移调与游戏记号

游戏基础键为 `Z X C V B N M ,`，音程为 `0 2 4 5 7 9 11 12`半音：

- 鼠标左键：降一个八度。
- 鼠标中键：升一个半音。
- 鼠标右键：升一个八度。

连续按键记号：

- 普通中音：`5`。
- 低八度：`5(左)`。
- 升半音：`4(中)`。
- 高八度：`2(右)`。
- 组合修饰：`4(左+中)` 或 `2(右+中)`。
- 高音 1 使用基础排逗号键：`1(,)`。
- 高音升 1：`1(中+,)`。

## 输出目录和文件

对于 `song.mp3`，默认生成 `output/song/`：

- `song-连续按键谱.md`：按自动检测的段落与小节排列的简洁按键顺序。
- `song-详细节奏谱.md`：十六分音符网格，包含延音和休止。
- `song-音符明细.csv`：开始、结束、原音高、移调后音高、置信度、小节、格位和游戏输入。
- `song-主旋律.mid`：量化后的移调主旋律。
- `song-口琴试听.wav`：离线合成的口琴风格单音试听。
- `song-分析报告.json`：检测速度、原始/输出音域、移调值、置信度统计、过滤音符数和警告。
- `stems/vocals.wav` 与 `stems/no_vocals.wav`：拖放入口默认保留的检查音轨。

## 置信度和失败条件

每个音符的置信度综合 pYIN 有声概率、片段内音高稳定性、能量和起点强度。

出现以下任一情况时失败，只保留日志以及已经成功生成的分离音轨，不生成正式谱面：

- 有效旋律总长度少于 8 秒。
- 有效音符少于 12 个。
- 中位音符置信度低于 0.55。
- 无法得到稳定拍点，且音符间隔网格估计也无法通过一致性检查。

可恢复问题使用清晰的中文消息报告，包括输入文件不存在、格式不支持、Python 版本不符合、依赖安装失败、模型下载失败和磁盘空间不足。处理前要求输出所在磁盘至少有 3 GB 可用空间；不足时不启动人声分离。

## 安装和本地性

- `提取口琴谱.bat` 优先使用现有 `.tools/audio-venv`。
- 如果环境不存在，使用 Python 3.12 创建项目内虚拟环境，并从锁定版本的 `requirements-audio.txt` 安装依赖。
- Demucs 模型在第一次处理时下载到用户模型缓存；批处理文件事先说明该步骤需要网络且可能较慢。
- 模型和依赖安装完成后，平常转谱不需要联网。

## 测试策略

### 单元测试

- 音高与游戏键位的全音域对应，包括重叠音高 C4/C5 的最少修饰键指法。
- 移调搜索优先级：不超界、少切换、少鼠标、少升半音、少移调。
- 音高平滑、短间隙桥接、伪短音合并和同音起点拆分。
- 十六分音符量化边界和最小一格时值。
- 连续谱不出现箭头或升号，详细谱正确表示延音与休止。

### 合成音频测试

程序生成包含以下特征的短音频，不依赖外部音乐文件：

- 不同音高的稳定长音。
- 三个连续同音。
- 半音滑音和颤音。
- 带无声间隔的短音。
- 人声主旋律与较弱伴奏的混合。

断言输出音高、音符数、起点顺序和移调后键位。

### 实际歌曲回归

使用用户提供的《晴天》音频作为本地回归样本：

- 全流程必须成功产生六类结果和两条分离音轨。
- 检测主旋律原始音域应与 D3–A4 大体一致，允许首尾泛音造成一个半音的偏差。
- 音符数应在 330–450 之间，避免纯 pYIN 方案把大量同音合并。
- 自动移调应选择 C 大调音级附近的低操作成本方案，输出音域必须位于游戏口琴范围内。
- 输出 MIDI 与 WAV 时长差小于 0.1 秒。

## 验收标准

- 用户可将含中文和空格的音频路径拖到批处理文件上并完成转谱。
- 首次安装和模型下载有明确进度；第二次处理不重新安装。
- 输出目录不会留下半成品；未使用 `--force` 时不覆盖已有结果。
- 连续按键谱将 `(左)`、`(中)`、`(右)` 直接写在对应数字旁边，高音 1 写为 `1(,)`。
- 详细节奏谱、CSV、MIDI、WAV、JSON 和分离音轨都可正常打开。
- 所有单元测试和合成音频测试通过，《晴天》回归满足规定的音域、音符数和输出完整性要求。

## 已知限制

- 工具优先处理单人演唱的流行歌曲；合唱、和声很强或人声分离失败时，可能产生额外音符。
- 快速说唱、气声、自由节拍、无稳定音高的念白不能可靠地转为单音旋律。
- 源分离与自动转谱都会有误差；生成的人声轨、CSV 置信度和试听 WAV 用于快速检查结果，不宣称所有歌曲都能完全无误地自动转谱。
